## 1. `/` — 홈

### 1.1 명세 상태

| 항목 | 값 |
|---|---|
| URL | `/` |
| 접근 권한 | 공개 |
| 주요 목적 | REFLO 소개, Google 로그인, 프로젝트 목록 진입, 새 리서치 시작 |
| 현재 구현 파일 | `source-react/app/page.tsx` |
| 현재 주요 컴포넌트 | `HomePage`, `AppHeader`, `Logo`, `Aurora`, `ShinyText`, `CreateProjectDialog` |
| 기준 요구사항 | 서비스 동작 명세 2장, 3장, 5장, 6장, 19장 |
| 관련 기술 결정 | TD-011의 PostgreSQL 소유권·파일 격리 원칙 |
| 구현 상태 | 디자인 프로토타입만 존재, 인증·실제 프로젝트 생성 미구현 |

### 1.2 목적과 책임

홈은 비로그인 사용자도 볼 수 있는 공개 화면이다. 다음 세 가지 책임만 가진다.

1. REFLO가 어떤 문제를 해결하는지 설명한다.
2. Google 로그인을 시작하고 로그인 상태를 표시한다.
3. 로그인 사용자가 프로젝트 목록으로 이동하거나 새 프로젝트 초안을 생성하게 한다.

홈에서는 기업 검색, 파일 업로드, 자료 수집, Excel 계산, 보고서 생성 작업을 실행하지 않는다. 해당 기능은 프로젝트 생성 후 각 process URL이 담당한다.

### 1.3 사용자 상태별 화면

| 세션 상태 | 헤더 오른쪽 | `Project` 내비게이션 | 히어로 CTA |
|---|---|---|---|
| 확인 중 | 로그인 버튼과 같은 크기의 로딩 자리표시자 | 클릭 대기 | 클릭 대기 |
| 비로그인 | `Google로 로그인` 버튼 | 로그인 시작 후 `/projects` 이동 | 로그인 시작 후 홈으로 복귀해 프로젝트 생성 모달 열기 |
| 로그인 | 사용자 아바타·메뉴 | `/projects` 이동 | 프로젝트 생성 모달 열기 |
| 세션 오류 | `Google로 로그인` 버튼과 재시도 안내 | 로그인 필요 | 로그인 필요 |

세션 확인 중에 현재 프로토타입의 가짜 `JE` 아바타를 먼저 표시하면 안 된다. 서버에서 세션을 확인한 뒤 실제 상태를 렌더링해 로그인 화면이 순간적으로 바뀌는 현상을 방지한다.

### 1.4 기본 사용자 흐름

#### 비로그인 사용자의 로그인

```text
홈 진입
  → Google로 로그인
  → Google 인증
  → 검증된 서버 세션 발급
  → 원래 의도한 URL 또는 동작으로 복귀
```

#### 새 리서치 시작

```text
새 리서치 시작
  → 비로그인이면 Google 인증
  → 프로젝트 이름 입력 모달
  → server에서 프로젝트 초안 생성
  → 실제 projectId 수신
  → /projects/{projectId}/process/setup 이동
```

프로젝트 생성 전에는 `/projects/new/process/setup`으로 이동하지 않는다. `new`는 현재 프로토타입의 임시 문자열이며 실제 식별자로 저장하거나 URL에 사용하지 않는다.

### 1.5 기존 디자인 재사용 판정

| 현재 영역 | 재사용 여부 | 구현 판단 |
|---|---|---|
| 고정 헤더 레이아웃 | 그대로 재사용 | 로그인 상태에 따라 오른쪽 액션 내용만 교체 |
| REFLO 로고 | 그대로 재사용 | 클릭 시 `/` 이동 |
| `Home`, `Project` 중앙 내비게이션 | 그대로 재사용 | `Project`에 인증 가드와 실제 라우팅 연결 |
| 도움말 `?` 버튼 | MVP에서 제거 | 현재 동작과 기준 문서가 없으므로 빈 버튼을 남기지 않음 |
| `JE` 아바타 | 형태 재사용 | 실제 Google 프로필 이미지 또는 이름 이니셜로 교체 |
| Aurora 배경 | 그대로 재사용 | 장식 전용이며 비즈니스 상태와 연결하지 않음 |
| ShinyText 제목 | 그대로 재사용 | `prefers-reduced-motion`에서는 정적 제목 표시 |
| 히어로 CTA 이미지·크기 | 그대로 재사용 | 인증 확인과 프로젝트 생성 흐름 연결 |
| `공식 자료 우선·수치 교차 검증·근거 연결` | 그대로 재사용 | 정적 제품 원칙 |
| 진행 단계 카드 | 디자인 재사용, 내용 수정 | 현재 6개를 문서 기준 7개 process 단계로 통일 |
| 프로젝트 이름 입력 모달 | 그대로 재사용 | 실제 `POST /api/projects` 연결과 오류 상태 추가 |
| 푸터 레이아웃 | 그대로 재사용 | `REFLO Prototype` 문구는 배포 시 `REFLO`로 교체 |

홈 디자인의 큰 레이아웃을 다시 만들 필요는 없다. 필수 변경은 인증 액션, 실제 프로젝트 생성, 7단계 표시, 빈 도움말 버튼 제거다.

### 1.6 목표 컴포넌트 구성

| 컴포넌트 | 책임 | 주요 입력 | 주요 출력·이벤트 |
|---|---|---|---|
| `HomeRoute` | 세션을 서버에서 확인하고 홈 초기 상태 제공 | 세션 쿠키 | `HomePage` 렌더링 |
| `HomePage` | 홈 레이아웃과 생성 모달 상태 조정 | `session` | 로그인·프로젝트 생성 이벤트 |
| `AppHeader` | 로고, 내비게이션, 인증 액션 표시 | `sessionStatus`, `user` | 홈·프로젝트 이동, 로그인, 사용자 메뉴 |
| `AuthAction` | 비로그인 Google 로그인 시작 | `returnTo`, `intent` | OAuth 시작 |
| `UserMenu` | 사용자 정보와 로그아웃 제공 | `displayName`, `email`, `avatarUrl` | `/projects` 이동, 로그아웃 |
| `HomeHero` | 제품 설명과 새 리서치 CTA | 정적 카피 | 새 리서치 시작 |
| `WorkflowOverview` | 실제 7단계 흐름 표시 | 정적 단계 목록 | 없음 |
| `CreateProjectDialog` | 프로젝트 이름 입력·검증·생성 | `open`, 초기값 | 생성 완료, 취소, 오류 |

`Aurora`, `ShinyText`, `Logo`는 표시 전용 컴포넌트로 유지한다. 이 컴포넌트 안에 인증이나 API 코드를 넣지 않는다.

### 1.7 표시할 7단계

홈의 진행 카드는 실제 process URL과 같은 순서를 사용한다.

| 번호 | 카드 제목 | 설명 | 연결 URL |
|---|---|---|---|
| 01 | 프로젝트 설정 | 기업·분기·기준일과 분석 범위 설정 | `process/setup` |
| 02 | 파일 업로드·검사 | 이전 PDF와 실제 Excel 구조·적합성 검사 | `process/files` |
| 03 | 투자 의견·조사 질문 | 잠정 의견과 투자 가설을 조사 질문으로 확정 | `process/hypothesis` |
| 04 | 자료 수집 및 계획 | 질문별 출처와 Excel 입력값 수집 계획 승인 | `process/research-plan` |
| 05 | 조사 결과 검증 | 원문 대조, 값 검증, 출처 충돌 해결 | `process/validation` |
| 06 | PER 밸류에이션 | 추정치와 Target PER을 사용자가 확정 | `process/valuation` |
| 07 | 페이지 내용 설정 | 페이지 구성 승인 후 보고서 생성·편집으로 연결 | `process/report-outline` |

카드는 홈에서는 설명 전용이다. 프로젝트가 없는 상태에서 특정 중간 단계로 바로 이동시킬 수 없으므로 버튼으로 만들지 않는다.

### 1.8 버튼과 상호작용

| ID | 화면 요소 | 노출 조건 | 동작 | 성공 결과 | 실패 처리 |
|---|---|---|---|---|---|
| HOME-BTN-01 | REFLO 로고 | 항상 | `/` 이동 | 홈 최상단 표시 | 없음 |
| HOME-BTN-02 | `Home` | 항상 | `/` 이동 | 활성 탭 유지 | 없음 |
| HOME-BTN-03 | `Project` | 항상 | 로그인 여부 확인 | 로그인 시 `/projects` | 비로그인 시 Google 인증 후 `/projects`, 인증 실패 안내 |
| HOME-BTN-04 | `Google로 로그인` | 비로그인 | Google OAuth 시작 | 검증된 세션 발급 후 `returnTo` 복귀 | 취소·실패 메시지와 재시도 |
| HOME-BTN-05 | 사용자 아바타 | 로그인 | 사용자 메뉴 열기 | 메뉴 표시 | 없음 |
| HOME-BTN-06 | 사용자 메뉴 `프로젝트` | 로그인 | `/projects` 이동 | 프로젝트 목록 표시 | 세션 만료 시 로그인 |
| HOME-BTN-07 | 사용자 메뉴 `로그아웃` | 로그인 | 세션 종료 | 공개 홈 상태로 전환 | 실패 시 메뉴 안에 재시도 표시 |
| HOME-BTN-08 | 히어로 `새 리서치` | 항상 | 로그인 확인 후 생성 모달 열기 | 모달 표시 | 인증 실패 안내 |
| HOME-BTN-09 | 모달 닫기 `×` | 모달 열림 | 입력을 버리고 닫기 | 이전 포커스로 복귀 | 없음 |
| HOME-BTN-10 | 모달 `취소` | 모달 열림 | 입력을 버리고 닫기 | 이전 포커스로 복귀 | 없음 |
| HOME-BTN-11 | 모달 `생성하기` | 이름 유효 | 프로젝트 초안 생성 요청 | 실제 setup URL로 이동 | 모달 유지, 오류 표시, 재시도 허용 |

`생성하기` 요청 중에는 버튼을 비활성화하고 진행 상태를 표시한다. Enter 제출과 버튼 클릭은 같은 로직을 사용한다. 빠른 중복 클릭으로 프로젝트가 두 개 생성되지 않아야 한다.

### 1.9 프로젝트 생성 모달

#### 입력

| 필드 | 타입 | 규칙 |
|---|---|---|
| 프로젝트 이름 | 문자열 | 앞뒤 공백 제거 후 1~60자 |

현재 디자인의 60자 제한과 글자 수 표시는 유지한다. 프로젝트 이름은 사용자가 프로젝트를 구분하는 표시용 값이며 기업명·종목코드·분기는 다음 setup 화면에서 별도로 확정한다.

#### 상태

| 상태 | 화면 |
|---|---|
| `idle` | 입력 가능, 이름이 없으면 생성 버튼 비활성 |
| `submitting` | 입력과 닫기 동작 잠금, 생성 버튼에 진행 상태 표시 |
| `validation_error` | 입력 아래에 1~60자 규칙 표시 |
| `request_error` | 모달을 유지하고 서버 오류 메시지·재시도 제공 |
| `success` | 모달을 닫고 반환된 setup URL로 이동 |

모달은 열릴 때 프로젝트 이름 입력으로 포커스를 이동한다. Escape와 배경 클릭으로 닫을 수 있고, 닫은 뒤에는 히어로 CTA로 포커스를 돌려준다. 제출 중에는 배경 클릭과 Escape로 닫지 않는다.

### 1.10 화면 데이터

#### 서버에서 받는 데이터

| 데이터 | 필드 | 용도 |
|---|---|---|
| 세션 | `authenticated`, `user` | 로그인 버튼과 사용자 메뉴 결정 |
| 사용자 | `userId`, `displayName`, `email`, `avatarUrl` | 헤더 표시 |
| 프로젝트 생성 결과 | `projectId`, `name`, `status`, `currentRoute`, `createdAt` | setup URL 이동 |

`userId`는 REFLO 내부의 불투명 식별자다. Google 사용자 ID와 프로젝트 소유권은 서버에서 세션으로 확인하며 클라이언트가 소유자 ID를 생성 요청에 보내지 않는다.

#### 정적 데이터

- 히어로 제목과 설명
- `공식 자료 우선·수치 교차 검증·근거 연결`
- 7단계 카드 제목과 설명
- 푸터 카피

정적 카피를 가져오기 위한 별도 API는 만들지 않는다.

### 1.11 클라이언트 상태

| 상태 | 타입 | 초기값 | 설명 |
|---|---|---|---|
| `sessionStatus` | `loading \| unauthenticated \| authenticated \| error` | 서버 초기값 | 인증 화면 결정 |
| `createDialogOpen` | boolean | `false` | 프로젝트 생성 모달 |
| `projectName` | string | `""` | 프로젝트 이름 입력 |
| `createStatus` | `idle \| submitting \| error` | `idle` | 생성 요청 상태 |
| `createError` | string 또는 null | `null` | 사용자 표시 오류 |
| `pendingIntent` | `projects \| create-project \| null` | `null` | 로그인 후 이어갈 동작 |
| `userMenuOpen` | boolean | `false` | 사용자 메뉴 |

세션과 프로젝트 데이터는 전역 하드코딩 변수나 `window` 객체에 저장하지 않는다. 인증 상태는 서버 세션이 권위값이고, 프로젝트 생성 결과는 서버 응답이 권위값이다.

### 1.12 API 계약

인증 구현 라이브러리는 아직 기술 결정 문서에서 확정되지 않았다. 아래 경로는 홈 화면이 의존할 애플리케이션 계약이며 OAuth 공급자 세부 구현은 서버 내부로 숨긴다.

#### `GET /api/auth/session`

공개 홈의 현재 세션을 조회한다.

로그인 응답:

```json
{
  "authenticated": true,
  "user": {
    "userId": "usr_01...",
    "displayName": "김애널리스트",
    "email": "analyst@example.com",
    "avatarUrl": "https://..."
  }
}
```

비로그인 응답:

```json
{
  "authenticated": false,
  "user": null
}
```

공개 화면이므로 비로그인은 정상 상태 `200`으로 반환한다.

#### `GET /api/auth/google/start`

Google 인증을 시작한다.

| 쿼리 | 필수 | 규칙 |
|---|---|---|
| `returnTo` | 예 | 같은 REFLO origin의 상대 경로만 허용 |
| `intent` | 아니요 | `projects` 또는 `create-project` |

서버는 `returnTo`와 `intent`를 변조할 수 없는 OAuth state에 연결한다. 외부 URL이나 다른 origin으로 리다이렉트하지 않는다.

#### `GET /api/auth/google/callback`

Google이 호출하는 서버 전용 callback이다. Google 응답을 검증하고 세션을 발급한 뒤 검증된 `returnTo`로 이동한다. `intent=create-project`이면 홈 복귀 후 프로젝트 생성 모달을 연다.

#### `POST /api/auth/logout`

현재 세션을 종료한다. 성공 시 `204 No Content`를 반환하고 홈의 비로그인 상태로 전환한다.

#### `POST /api/projects`

로그인 사용자의 프로젝트 초안을 생성한다.

요청:

```http
POST /api/projects
Content-Type: application/json
Idempotency-Key: 7a4d...
```

```json
{
  "name": "삼성전기 2026년 2분기 리서치"
}
```

`Idempotency-Key`는 같은 생성 요청이 재전송돼도 프로젝트가 한 번만 생성되게 하는 요청 식별자다.

성공 응답:

```json
{
  "project": {
    "projectId": "prj_01...",
    "name": "삼성전기 2026년 2분기 리서치",
    "status": "draft",
    "currentRoute": "/projects/prj_01.../process/setup",
    "createdAt": "2026-07-24T12:00:00Z"
  }
}
```

| 상태 코드 | 오류 코드 | 화면 처리 |
|---|---|---|
| `400` | `INVALID_PROJECT_NAME` | 이름 입력 아래 검증 메시지 |
| `401` | `AUTH_REQUIRED` | 모달 상태 보존 후 로그인 재개 |
| `409` | `IDEMPOTENCY_CONFLICT` | 기존 성공 결과 조회 후 해당 프로젝트로 이동 |
| `429` | `RATE_LIMITED` | 잠시 후 재시도 안내 |
| `500` | `PROJECT_CREATE_FAILED` | 모달 유지, 재시도 제공 |

### 1.13 저장 모델

프로젝트 생성 시 PostgreSQL에 최소한 다음 값을 저장한다.

| 필드 | 규칙 |
|---|---|
| `project_id` | 서버 생성 고유 식별자 |
| `owner_google_user_id` | 요청값이 아니라 검증된 세션에서 획득 |
| `name` | 정규화된 1~60자 프로젝트 이름 |
| `status` | `draft` |
| `current_stage` | `setup` |
| `created_at`, `updated_at` | 서버 시각 |
| `version` | 초기값 1 |

홈에서 아직 파일을 만들지 않으므로 S3 객체 저장소, Temporal, PDF 워커, Excel 워커는 호출하지 않는다.

### 1.14 기술 배치

| 기술·영역 | 홈에서의 위치 | 판단 |
|---|---|---|
| Next.js App Router | `/` route와 서버 세션 초기화 | 사용 |
| React Client Component | 생성 모달·사용자 메뉴 상호작용 | 사용 |
| Google OAuth | 로그인·세션 발급 | 필수, 구체 라이브러리는 미확정 |
| PostgreSQL | 사용자와 프로젝트 초안 소유권 저장 | 사용 |
| OGL `Aurora` | 홈 배경 장식 | 현재 디자인 보존을 위해 사용 |
| CSS·ShinyText | 홈 제목 표현 | 사용, 모션 감소 설정 지원 |
| SpreadJS | 없음 | 홈에 로드하지 않음 |
| Aspose.Cells | 없음 | 홈에서 호출하지 않음 |
| S3 호환 저장소 | 없음 | 파일이 없는 단계이므로 호출하지 않음 |

홈 번들에 SpreadJS, PDF, Excel, Agent 관련 코드를 포함하지 않는다. 해당 기술은 실제 사용하는 URL에서 지연 로드한다.

### 1.15 보안 규칙

1. 세션 쿠키는 서버에서 발급하고 JavaScript가 읽을 수 없는 `HttpOnly`, HTTPS 전용 `Secure`, 적절한 `SameSite` 정책을 적용한다.
2. Google 사용자 ID와 프로젝트 소유자는 서버 세션에서만 결정한다.
3. `returnTo`는 같은 서비스의 상대 경로만 허용한다.
4. 프로젝트 생성 요청의 사용자 ID, 소유자 ID, 초기 진행 단계는 클라이언트 입력을 받지 않는다.
5. 로그아웃과 프로젝트 생성 같은 상태 변경 요청에는 CSRF 방어를 적용한다.
6. 사용자 이름·이메일·프로젝트 이름은 HTML로 해석하지 않고 텍스트로 렌더링한다.
7. 프로젝트 생성 중복 요청은 요청 식별자와 서버 제약으로 한 번만 반영한다.

### 1.16 오류·예외 상태

| 상황 | 사용자 화면 | 후속 동작 |
|---|---|---|
| Google 로그인 취소 | 홈 유지, 취소 안내 | 다시 로그인 가능 |
| Google 로그인 실패 | 홈 유지, 실패 안내 | 재시도 |
| 세션 만료 | 진행 중 입력 보존 | 재로그인 후 의도한 동작 재개 |
| 프로젝트 이름 공백 | 생성 버튼 비활성 | 입력 대기 |
| 프로젝트 생성 실패 | 모달과 이름 유지 | 재시도 |
| 네트워크 끊김 | 연결 오류와 재시도 | 복구 후 같은 요청 식별자로 재전송 |
| 프로필 이미지 실패 | 이름 이니셜 아바타 | 메뉴 기능 유지 |
| Aurora/WebGL 실패 | 정적 어두운 배경 | 로그인·생성 기능 유지 |
| 모션 감소 설정 | 애니메이션 없는 제목·배경 | 기능 동일 |

장식 요소가 실패해도 로그인과 프로젝트 생성은 동작해야 한다.

### 1.17 현재 구현과 목표의 차이

| 새 리서치가 로컬 상태만 변경 | 서버 프로젝트 초안 생성 | 필수 |

### 1.18 구현 순서

1. Google 인증 라이브러리와 세션 저장 방식을 별도 기술 결정으로 확정한다.
2. 서버 세션 조회와 Google 로그인·callback·로그아웃을 구현한다.
3. PostgreSQL 사용자·프로젝트 최소 모델과 `POST /api/projects`를 구현한다.
4. 기존 `AppHeader`에 세션 상태별 액션을 연결한다.
5. 기존 `CreateProjectDialog`에 실제 생성 요청과 오류 상태를 연결한다.
6. 가짜 `"new"` 프로젝트 이동을 실제 응답의 `currentRoute` 이동으로 교체한다.
7. 진행 카드 내용을 7단계로 교체한다.
8. 접근성·실패·중복 요청 시나리오를 자동 테스트한다.

### 1.19 완료 조건

- [ ] 비로그인 사용자가 `/`을 정상적으로 볼 수 있다.
- [ ] 비로그인 헤더에 `Google로 로그인`이 표시되고 가짜 아바타는 표시되지 않는다.
- [ ] 로그인 성공 후 검증된 서버 세션이 발급된다.
- [ ] `Project` 클릭은 로그인 사용자를 `/projects`로 이동시킨다.
- [ ] 비로그인 상태의 `Project` 클릭은 로그인 후 `/projects`로 복귀한다.
- [ ] 비로그인 상태의 `새 리서치` 클릭은 로그인 후 프로젝트 생성 모달을 연다.
- [ ] 프로젝트 이름은 앞뒤 공백 제거 후 1~60자로 검증된다.
- [ ] 프로젝트 생성은 서버에서 한 번만 처리되고 실제 `projectId`를 반환한다.
- [ ] 생성 성공 후 `/projects/{projectId}/process/setup`으로 이동한다.
- [ ] 생성 실패 시 모달과 입력값이 유지되고 재시도할 수 있다.
- [ ] 다른 사용자의 ID를 요청에 넣어 프로젝트 소유권을 바꿀 수 없다.
- [ ] 홈 진행 카드가 실제 7개 process 단계와 일치한다.
- [ ] 화면에 동작하지 않는 버튼이 남아 있지 않다.
- [ ] 키보드만으로 로그인, 모달 열기·입력·제출·닫기가 가능하다.
- [ ] 모션 감소 환경과 WebGL 실패 환경에서도 핵심 동작이 가능하다.
- [ ] 홈에서 SpreadJS, PDF·Excel 워커, Temporal, Agent 코드를 로드하거나 호출하지 않는다.

### 1.21 아직 필요한 기술 결정

홈의 제품 동작은 확정할 수 있지만 다음 기술 선택은 두 기준 문서에 아직 없다.

1. Google OAuth와 세션 구현 라이브러리
2. 세션 저장 위치와 만료·갱신 시간
3. 사용자 레코드와 Google 계정 연결 방식
4. CSRF 구현 방식

이 항목은 인증 구현 전에 `REFLO_TECHNICAL_DECISIONS_v1.md`에 새 결정 ID로 추가해야 한다. 인증 기술이 미확정이어도 홈 UI 재사용 범위, 버튼 동작, 프로젝트 생성 계약은 이 명세대로 유지한다.
