네. 두 흐름은 명확하게 구분돼야 합니다.

현재 화면은 STEP 04와 STEP 05에서 가설과 Excel을 탭으로 나누지만, 백엔드는 하나의 자료 수집 작업과 LLM 처리 흐름에 둘을 함께 넣고 있습니다. 즉, 화면만 나뉘었고 처리 과정은 충분히 분리되지 않았습니다.

아래는 이 서비스에 맞는 최종 정상 동작입니다.

# 1. 이 서비스가 하는 일

이 서비스는 기업의 특정 분기 실적을 조사해 투자 리포트를 만드는 시스템입니다.

사용자는 다음 자료를 제공합니다.

1. 분석할 기업
2. 기준 연도와 분기
3. 보고서 기준일
4. 기존 리포트 PDF
5. 계산과 표·차트가 들어 있는 Excel
6. 잠정 투자의견과 투자 가설

서비스는 이를 바탕으로 다음 결과를 만듭니다.

1. 투자 가설별 조사 결과
2. 가설별 긍정·중립·부정·판단 불가 결론
3. 공식 자료로 검증된 Excel 실제값
4. 검증된 Excel 사본
5. PER 등 밸류에이션 결과
6. 최종 투자 리포트

전체 단계는 다음과 같습니다.

1. 기업·기간 설정
2. 과거 PDF와 Excel 분석
3. 투자 가설과 조사 질문 생성
4. 가설 자료와 Excel 자료 수집 계획
5. 조사 결과와 Excel 값 검증
6. 밸류에이션
7. 리포트 생성

STEP 04와 STEP 05는 다음 구조가 돼야 합니다.

```text
STEP 04 자료 수집 및 계획
├─ 가설 자료 수집 계획
└─ Excel 자료 수집 계획

자료 수집 실행
├─ 가설 조사 파이프라인
└─ Excel 숫자 수집 파이프라인

STEP 05 조사 결과 검증
├─ 가설 결과 검증
└─ Excel 입력값 검증

두 검증 모두 완료
└─ 검증된 Excel 생성 → 밸류에이션
```

# 2. 두 흐름의 차이

| 구분 | 가설 조사 | Excel 조사 |
|---|---|---|
| 목적 | 투자 가설이 맞는지 판단 | Excel의 정확한 셀에 공식 숫자 입력 |
| 주요 결과 | 긍정·중립·부정·판단 불가와 한 줄 답변 | 검증된 숫자와 Excel 변경안 |
| AI 사용 | 근거 탐색·정리·한 줄 답변 작성 | 사용 금지 |
| 숫자 선택 | AI 후보 + 코드·검증 AI 검사 | 규칙 기반 코드만 사용 |
| 주요 출처 | DART, IR, 뉴스, 사용자 자료, KRX, ECOS | DART, KRX, ECOS, 구조화된 공식 데이터 |
| 결과 단위 | 질문과 지표 | Excel 셀 |
| 재조사 | 질문·지표 단위 | 실패한 셀·지표 단위 |
| 최종 확인 | 근거 원문과 답변 | 원문 숫자와 Excel Before/After |

같은 DART 보고서를 두 흐름이 사용할 수는 있습니다. 하지만 사용하는 방법이 다릅니다.

- 가설 조사: 보고서 문장을 읽고 투자 가설의 근거로 사용
- Excel 조사: 보고서의 정확한 재무제표 행과 금액 칸을 규칙으로 선택

DART 원문은 한 번만 저장해도 되지만, 가설 근거와 Excel 근거는 별도로 만들어야 합니다.

# 3. 가설 자료 수집과 검증의 전체 과정

## 3.1 조사 질문을 검사한다

STEP 03에서 승인된 질문마다 다음 정보가 있어야 합니다.

1. 질문 ID
2. 질문 내용
3. 질문의 목적
4. 확인할 지표
5. 조사 기간
6. 비교 기준
7. 필요한 출처
8. 판정 규칙

예시 질문:

> 대덕전자의 2026년 1분기 AI 서버·데이터센터용 FCBGA 매출 또는 출하량은 전년 동기와 전분기 대비 얼마나 변했으며, 수주·고객 수요 지표가 예상 초과 강세를 뒷받침하는가?

이 질문은 내부적으로 다음처럼 나눠야 합니다.

1. 2026년 1분기 FCBGA 매출 또는 출하량
2. 2025년 1분기와 비교한 증감률
3. 2025년 4분기와 비교한 증감률
4. 회사가 공개한 수주 지표
5. 회사가 공개한 고객 수요 지표
6. 회사의 이전 전망
7. 실제 결과가 이전 전망보다 강했는지

하나의 긴 질문을 AI에 그대로 던지고 답하게 하면 안 됩니다.

## 3.2 질문별 출처를 연결한다

출처 종류만 선택하는 것이 아니라 실제 자료를 질문과 연결해야 합니다.

예:

```text
질문 1
├─ 2026년 1분기 IR PDF
├─ 2025년 4분기 IR PDF
├─ 2025년 1분기 IR PDF
├─ 2026년 1분기보고서
└─ 기준 기간 뉴스
```

각 자료에는 역할을 붙입니다.

- 권위 출처: 결론의 기준이 되는 공식 자료
- 확인 출처: 권위 출처의 내용을 확인하는 자료
- 비교 출처: 과거 값 또는 시장 반응 비교 자료

예:

- FCBGA 매출·출하량: 회사 IR
- 전체 회사 매출: DART
- 수주·고객 수요: 회사 IR 또는 공식 발표
- 시장 반응: 뉴스
- 주가 반응: KRX

뉴스만으로 회사 매출 숫자를 확정하면 안 됩니다.

## 3.3 수집할 기간을 정한다

질문마다 자료 수집 기간을 정합니다.

예:

```text
현재 기간: 2026-01-01 ~ 2026-03-31
전년 동기: 2025-01-01 ~ 2025-03-31
전분기: 2025-10-01 ~ 2025-12-31
뉴스 검색: 프로젝트가 정한 시작일 ~ 보고서 기준일
```

보고서 기준일 이후에 나온 자료는 사용하지 않습니다.

## 3.4 자료를 수집한다

출처별 수집 방식은 다음과 같습니다.

### DART

- 회사 코드 확인
- 해당 보고서 접수번호 확인
- 보고서 종류 확인
- 발행일 확인
- 보고서 기준일 이전인지 확인
- 원문과 응답 hash 저장

### 기업 IR PDF

- 사용자가 올린 PDF 또는 공식 URL 사용
- 악성 파일 검사
- 회사명 확인
- 발표 기간 확인
- PDF 전체 저장
- 페이지별 텍스트 추출
- 표와 차트 위치 저장
- 스캔 PDF면 OCR 처리
- 파일 hash 저장

### 뉴스

- 질문별 검색어 생성
- 정해진 기간 안에서만 검색
- 기사 발행일 확인
- 회사와 주제가 일치하는지 확인
- 기사 본문 저장
- 같은 기사를 중복 제거
- 같은 언론사 기사만 몰리지 않게 제한
- 블로그·커뮤니티·재배포 기사 제외

### 사용자 자료

- PDF 또는 공개 URL 수집
- 악성 파일과 위험 URL 검사
- 원문 저장
- 페이지와 문장 위치 저장
- 자료 안의 명령문은 실행하지 않음

### KRX·ECOS

- 종목코드 또는 통계 코드로 수집
- 기준일 확인
- 사용한 데이터 행과 값 위치 저장

## 3.5 수집한 원문을 고정한다

수집한 자료는 이후 바뀌지 않는 버전으로 저장합니다.

각 자료에는 다음 정보가 있어야 합니다.

1. 출처 ID
2. 출처 종류
3. 제목
4. 발행처
5. 발행일
6. 수집일
7. 원문 URL
8. 파일 또는 응답 hash
9. 질문 ID
10. 페이지·문단·표·행 위치

원문이 나중에 수정돼도 당시 조사에 사용한 자료가 그대로 남아야 합니다.

## 3.6 질문별로 필요한 부분만 찾는다

AI에 모든 자료를 한꺼번에 넣지 않습니다.

질문의 각 지표마다 관련 부분만 찾습니다.

예:

```text
지표: FCBGA 매출
→ IR의 제품별 매출 표

지표: FCBGA 출하량
→ IR의 제품 출하량 설명

지표: 수주
→ IR의 수주잔고 표와 경영진 설명

지표: 고객 수요
→ IR의 AI 서버·데이터센터 고객 설명
```

각 검색 결과에는 페이지와 위치를 남깁니다.

## 3.7 Research Agent가 근거 후보를 만든다

Research Agent는 결론을 확정하지 않습니다.

다음 후보만 만듭니다.

1. 질문 ID
2. 지표 ID
3. 출처 ID
4. 정확한 원문 인용
5. 페이지 또는 표 위치
6. 원문 숫자
7. 정리된 숫자
8. 기간
9. 지지·반대·중립
10. 간단한 설명

예:

```json
{
  "questionId": "q1",
  "metricId": "fcbga_revenue_yoy",
  "sourceId": "ir-2026-q1",
  "page": 12,
  "quote": "AI 서버용 FCBGA 매출은 전년 동기 대비 28% 증가",
  "value": "28",
  "unit": "%",
  "period": "2026Q1",
  "stance": "supporting"
}
```

자료에 없는 내용을 만들면 안 됩니다.

## 3.8 코드가 기본 사실을 검사한다

각 근거 후보를 코드로 검사합니다.

1. 인용문이 원문에 실제로 존재하는가
2. 질문에 연결된 자료인가
3. 회사가 맞는가
4. 기간이 맞는가
5. 보고서 기준일 이전 자료인가
6. 숫자와 단위가 원문과 같은가
7. 페이지와 표 위치가 존재하는가
8. 지표가 질문에서 요구한 지표인가
9. 허용된 출처인가

하나라도 실패하면 근거에서 제외합니다.

## 3.9 Validation Agent가 의미를 검사한다

Validation Agent는 통과한 원문과 후보를 다시 읽습니다.

다음을 확인합니다.

1. 인용문이 주장과 실제로 연결되는가
2. 매출과 출하량을 혼동하지 않았는가
3. 전체 회사 매출과 FCBGA 매출을 혼동하지 않았는가
4. 전년 동기와 전분기를 혼동하지 않았는가
5. 회사 전망과 시장 전망을 혼동하지 않았는가
6. 단순 증가를 예상 초과로 잘못 표현하지 않았는가
7. 원문의 주의사항이 빠지지 않았는가

Validation Agent도 새로운 사실을 추가하면 안 됩니다.

## 3.10 숫자 계산을 코드로 다시 확인한다

증감률은 AI가 계산한 값을 믿지 않습니다.

```text
전년 동기 증감률
= (현재 값 - 전년 동기 값) / 전년 동기 값 × 100

전분기 증감률
= (현재 값 - 전분기 값) / 전분기 값 × 100
```

원문에 증감률이 직접 있으면 원문 값과 계산값을 비교합니다.

차이가 크면 사용자 검토 대상으로 보냅니다.

## 3.11 근거 충돌을 찾는다

같은 지표와 기간에 다른 값이 있으면 충돌로 표시합니다.

예:

```text
IR: FCBGA 매출 +28%
뉴스: FCBGA 매출 +20%
```

충돌 상태에서는 최종 답변을 확정하지 않습니다.

사용자가 권위 출처를 선택하거나 재조사를 요청해야 합니다.

## 3.12 질문의 자료 충분성을 판단한다

질문에 필요한 지표가 모두 있는지 확인합니다.

예시 질문은 최소한 다음이 필요합니다.

- 전년 동기 변화
- 전분기 변화
- 수주 또는 고객 수요
- 예상 초과를 비교할 이전 전망

판정은 다음과 같습니다.

- 충분: 필수 지표가 모두 있고 충돌 없음
- 조건부: 일부 보조 자료가 부족하지만 결론 가능
- 부족: 필수 지표 누락
- 재조사 중: 선택한 질문을 다시 조사 중

## 3.13 긍정·중립·부정·판단 불가를 코드로 정한다

최종 판정 기준은 질문 승인 시 함께 저장해야 합니다.

예시:

- 긍정: 매출·출하량 증가와 예상 초과 수요 근거가 모두 확인됨
- 중립: 지표가 엇갈리거나 예상 초과 여부가 명확하지 않음
- 부정: 실적과 수요 지표가 약화되거나 가설과 반대
- 판단 불가: 필수 자료가 공개되지 않음

AI가 마음대로 판정 기준을 바꾸면 안 됩니다.

## 3.14 AI가 한 줄 답변을 작성한다

판정이 끝난 다음에만 AI가 문장을 작성합니다.

AI 입력에는 검증을 통과한 근거만 넣습니다.

AI 출력은 다음 형식으로 제한합니다.

```json
{
  "questionId": "q1",
  "verdict": "positive",
  "oneLineAnswer": "FCBGA 매출은 전년 동기 대비 28%, 전분기 대비 12% 증가했고 수주도 이전 전망을 웃돌아 예상 초과 강세가 확인됐다.",
  "evidenceIds": ["e1", "e2", "e3"],
  "caveat": null
}
```

서버가 다시 검사합니다.

1. 사용한 근거 ID가 모두 승인된 근거인가
2. 답변에 나온 숫자가 실제 근거에 있는가
3. 판정 결과와 문장 방향이 같은가
4. 자료에 없는 회사·기간·제품을 추가하지 않았는가
5. 판단 불가인데 확정적으로 표현하지 않았는가

검사를 통과하지 못하면 문장을 게시하지 않습니다.

## 3.15 사용자가 가설 결과를 검증한다

STEP 05 가설 탭에는 다음을 표시합니다.

1. 질문
2. 긍정·중립·부정·판단 불가
3. AI 한 줄 답변
4. 필수 지표별 결과
5. 지지 근거
6. 반대 근거
7. 충돌
8. 부족한 자료

근거를 클릭하면 오른쪽 패널에서 원문이 열립니다.

- DART: 재무제표 행·금액 하이라이트
- IR PDF: 페이지와 문장·표 하이라이트
- 뉴스: 저장된 기사 본문과 문장 하이라이트
- 사용자 PDF: 페이지와 문장 하이라이트
- KRX·ECOS: 사용한 데이터 행 하이라이트

## 3.16 사용자 결정

사용자는 다음을 할 수 있습니다.

- 결과 승인
- 근거 반려
- 반려 철회
- 충돌 출처 선택
- 해당 질문만 재조사
- 조건부 결과 승인

재조사는 전체 계획이 아니라 선택한 질문과 지표만 다시 실행해야 합니다.

# 4. Excel 자료 수집과 검증의 전체 과정

## 4.1 PDF와 Excel의 연결 결과를 가져온다

STEP 02에서 기존 PDF 리포트 요소와 Excel 위치를 연결합니다.

예:

```text
PDF 손익계산서 표
→ Excel 12_실적추이!A5:L25

PDF 분기 실적 차트
→ Excel 01_분기실적!B10:M25
```

STEP 04에서는 연결된 대상 중 이번 보고서에서 갱신할 항목을 찾습니다.

## 4.2 Excel 입력 대상을 만든다

각 숫자는 정확한 입력 대상을 가져야 합니다.

```json
{
  "targetId": "revenue-2026-q1",
  "sheetName": "손익계산서",
  "address": "E12",
  "metricId": "revenue",
  "period": "2026Q1",
  "periodBasis": "year_to_date",
  "scope": "CFS",
  "unit": "KRW_100M",
  "valueKind": "actual",
  "source": "DART"
}
```

필수 정보:

1. 시트
2. 셀
3. 지표
4. 기간
5. 연간·누적·단일 분기 구분
6. 연결·별도 구분
7. 단위
8. 실제값·전망값 구분
9. 권위 출처
10. 쓰기 허용 여부

## 4.3 대상별 처리 방법을 정한다

각 대상은 다음 중 하나입니다.

- 수집 필요: 공식 자료에서 새 값을 가져옴
- 기존값 유지: 기존 Excel 실제값 유지
- 후속 단계: 전망·밸류에이션에서 처리
- 연결 확인: PDF와 Excel 위치를 다시 연결해야 함
- 사용자 입력: 자동 수집할 수 없음

전망값을 DART에서 가져오면 안 됩니다.

## 4.4 지표별 권위 출처를 정한다

| 값 | 권위 출처 |
|---|---|
| 재무제표 실제값 | DART |
| 기준일 주가 | KRX |
| 환율·금리 | ECOS |
| 수주잔고·제품별 실적 | 기업 IR 또는 사용자 확인 |
| 전망·컨센서스 | 별도 라이선스 출처 또는 사용자 입력 |
| 뉴스 | Excel 권위 출처로 사용 금지 |

IR의 표에서 숫자를 가져오는 경우에도 LLM이 자동으로 숫자를 골라 Excel에 넣으면 안 됩니다.

표 추출 코드가 정확한 행과 열을 찾고 사용자가 확인해야 합니다. 정확히 찾지 못하면 수동 입력으로 전환합니다.

## 4.5 공식 데이터를 수집한다

### DART

Excel 대상 기간을 기준으로 정확한 보고서를 선택합니다.

- 1분기: 1분기보고서
- 상반기: 반기보고서
- 3분기 누적: 3분기보고서
- 연간: 사업보고서

정정공시가 있다면 기준일 이전의 가장 최신 정정본을 사용합니다.

연간보고서와 분기보고서를 별도 원문으로 저장합니다.

### KRX

- 정확한 종목코드
- 보고서 기준일 또는 직전 거래일
- 종가
- 거래일
- 사용한 API 행

### ECOS

- 정확한 통계 코드
- 항목 코드
- 주기
- 기준일
- 사용한 데이터 행

## 4.6 DART 재무제표와 계정을 선택한다

지표별 규칙을 사용합니다.

예:

```text
매출액
├─ 허용 재무제표: 손익계산서, 포괄손익계산서
├─ 범위: 연결
├─ 허용 계정 ID 목록
└─ 허용 계정명 목록
```

선택 조건:

1. 회사 일치
2. 사업연도 일치
3. 보고서 종류 일치
4. 연결·별도 일치
5. 재무제표 일치
6. 계정 ID 일치
7. 기간 일치

후보가 정확히 하나일 때만 자동 선택합니다.

- 0개: 계정 없음
- 2개 이상: 계정 후보 여러 개
- 불명확: 사용자 검토 필요

LLM이나 문자열 유사도로 선택하지 않습니다.

## 4.7 정확한 금액 칸을 선택한다

재무상태표는 특정 시점 잔액입니다.

손익계산서와 현금흐름표는 누적 기간 값일 수 있습니다.

단일 분기 값은 코드로 계산합니다.

```text
1분기 단독 = 1분기 누적
2분기 단독 = 반기 누적 - 1분기 누적
3분기 단독 = 3분기 누적 - 반기 누적
4분기 단독 = 연간 - 3분기 누적
```

어떤 보고서의 어떤 금액 칸을 사용했는지 저장합니다.

## 4.8 단위를 변환한다

예:

```text
DART 원문: 1,234,567,890,000원
Excel 단위: 억원
Excel 입력값: 12,345.6789
```

단위 변환은 Decimal 기반 코드로 처리합니다.

원본 값, 원본 단위, 변환값, Excel 단위, 변환 배수를 모두 저장합니다.

## 4.9 파생값을 계산한다

다음 값은 코드로 계산합니다.

- 영업이익률
- 순이익률
- 성장률
- 부채비율
- 단일 분기 실적

계산식과 사용한 원문 값 ID를 모두 저장합니다.

## 4.10 Excel 값 전용 검사를 실행한다

다음을 모두 검사합니다.

1. 회사
2. 기간
3. 보고서
4. 공시일
5. 연결·별도
6. 재무제표
7. 계정

10. 통화
11. 단위
12. 대상 셀
13. 수식 셀 여부
14. 중복 대상 여부
15. 원문 hash
16. Excel 구조 hash

하나라도 실패하면 변경안을 만들지 않습니다.

## 4.11 검증된 값 기록을 만든다

각 Excel 값은 다음 연결을 가져야 합니다.

## 4.15 Excel 사본에 반영한다

5. 승인된 값만 입력

7. 새 Excel 파일 저장

## 4.16 결과 Excel을 다시 검사한다

1. 승인한 셀에 정확한 값이 들어갔는가
2. 거절·미결정 셀이 바뀌지 않았는가
3. 수식이 유지됐는가
4. 시트가 유지됐는가
5. 병합 셀이 유지됐는가
6. 차트가 유지됐는가
7. 파일이 정상적으로 열리는가

# 7. 현재 구현과 다른 점

현재 코드 상태는 다음과 같습니다.

1. STEP 04 화면은 가설과 Excel을 탭으로 분리합니다.
2. STEP 05 화면도 가설과 Excel을 탭으로 분리합니다.
3. 하지만 백엔드는 두 대상을 하나의 계획과 하나의 수집 작업에 넣습니다.

8. 따라서 처리 과정은 아직 완전히 분리되지 않았습니다.
