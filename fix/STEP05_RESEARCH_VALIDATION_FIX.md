# STEP 05 조사 결과 검증 수정안

## 1. 반드시 지켜야 하는 원칙

1. Excel에 들어갈 숫자는 LLM이 고르지 않는다.
2. DART 숫자는 규칙 기반 코드가 고른다.
3. 사용자는 Excel의 숫자를 클릭해서 그 숫자의 DART 원문을 바로 확인할 수 있어야 한다.
4. 오른쪽 원문 패널에는 실제로 사용한 보고서와 재무제표가 열려야 한다.
5. 실제로 사용한 계정 행과 금액 칸이 하이라이트되어야 한다.
6. 원문을 확인할 수 없는 숫자는 Excel에 반영하지 않는다.
7. 사용자가 승인하지 않은 Excel 변경안은 자동으로 승인하지 않는다.
8. 원본 Excel은 수정하지 않고 새 Excel 파일을 만든다.

---

## 2. 사용자가 보게 될 최종 흐름

예시는 `2026년 1분기 연결 손익계산서의 매출액`을 Excel에 넣는 경우다.

1. 시스템이 Excel에서 값을 채워야 할 셀을 찾는다.
2. 해당 셀의 지표가 `매출액`, 기간이 `2026년 1분기`, 범위가 `연결`이라는 것을 확인한다.
3. DART에서 해당 회사의 2026년 1분기보고서를 가져온다.
4. 2026년 1분기보고서의 연결 손익계산서 또는 연결 포괄손익계산서를 선택한다.
5. 미리 등록된 계정 ID와 계정명 규칙으로 매출액 행을 찾는다.
6. 해당 행에서 2026년 1분기에 맞는 금액 칸을 선택한다.
7. 원 단위 금액을 Excel에서 사용하는 단위로 변환한다.
8. 회사·기간·보고서·재무제표·계정·단위를 코드로 검사한다.
9. 검사를 통과하면 Excel 변경안을 만든다.
10. 조사 결과 검증 화면에서 사용자가 해당 Excel 셀을 클릭한다.
11. 오른쪽 패널에 2026년 1분기보고서의 연결 손익계산서가 열린다.
12. 매출액 행과 실제로 사용한 금액 칸이 하이라이트된다.
13. 사용자가 원문과 변경값을 확인하고 승인하거나 거절한다.
14. 승인된 값만 Excel 사본에 반영한다.
15. 저장한 Excel을 다시 열어 값과 수식이 정상인지 검사한다.

## 3. 조사 결과 검증 화면 구성

조사 결과 검증 화면은 `가설 검증`과 `Excel 검증` 두 영역으로 나눈다.

### 3.1 가설 검증

가설 질문마다 다음 내용을 보여준다.

- 질문
- 검증할 지표 목록
- 조사 결과
- 결과를 지지하는 근거
- 결과와 반대되는 근거
- 사용한 출처
- 기간
- 검증 상태
- 사용자 결정

### 3.2 Excel 검증

Excel 검증 화면은 좌우 두 패널로 구성한다.

#### 왼쪽 패널

- Excel 시트 목록
- Excel 셀 또는 입력 대상 목록
- 기존 값
- 변경할 값
- 단위
- 검증 상태
- 승인 상태

#### 오른쪽 패널

- DART 보고서 정보
- DART 재무제표 원문 표
- 사용한 계정 행
- 사용한 금액 칸
- 계산 과정
- DART 원문 링크
- 코드 검증 결과
- 승인·거절 버튼

## 4. Excel 값을 클릭했을 때의 동작

### 4.1 직접 가져온 값

사용자가 Excel 손익계산서 시트의 `2026년 1분기 매출액` 값을 클릭하면 다음처럼 동작해야 한다.

1. 클릭한 셀의 `targetId`를 찾는다.
2. `targetId`에 연결된 검증 결과를 찾는다.
3. 검증 결과에 연결된 DART 근거를 찾는다.
4. DART 근거에 저장된 정확한 접수번호를 사용한다.
5. 오른쪽 패널에 해당 접수번호의 보고서를 표시한다.
6. 해당 보고서의 연결 손익계산서를 표시한다.
7. 매출액 계정 행으로 자동 스크롤한다.
8. 매출액 계정명을 하이라이트한다.
9. 실제로 선택한 금액 칸을 더 진한 색으로 하이라이트한다.

오른쪽 패널 상단에는 다음 내용을 표시한다.

```text
회사: 대덕전자
보고서: 2026년 1분기보고서
공시일: 2026-05-15
재무제표: 연결 포괄손익계산서
계정: 매출액
기간: 2026-01-01 ~ 2026-03-31
원문 단위: 원
Excel 단위: 억원
```

### 4.2 계산해서 만든 값

2분기 단독 실적처럼 두 개 이상의 DART 값으로 계산한 경우에는 모든 원문을 보여준다.

예:

```text
2026년 2분기 단독 매출액
= 2026년 반기 누적 매출액
- 2026년 1분기 누적 매출액
```

오른쪽 패널에는 다음을 표시한다.

1. 2026년 반기보고서의 매출액 행과 사용 금액
2. 2026년 1분기보고서의 매출액 행과 사용 금액
3. 계산식
4. 계산 결과
5. 단위 변환 과정

두 원문은 탭으로 전환하거나 위아래로 나누어 확인할 수 있게 한다.

### 4.3 원문을 찾을 수 없는 값

다음 상황에서는 오른쪽 패널에 값을 표시하지 않고 차단 사유를 보여준다.

- 보고서가 아직 공시되지 않음
- 계정을 찾지 못함
- 같은 계정 후보가 두 개 이상임
- 연결/별도 구분이 맞지 않음
- 기간이 맞지 않음
- 단위를 알 수 없음
- 어떤 금액 칸을 사용해야 하는지 결정할 수 없음

이 값에는 승인 버튼을 표시하지 않는다.

## 5. DART 원문 패널 구현 방식

외부 DART 웹페이지를 오른쪽 패널에 그대로 넣지 않는다.

외부 페이지는 화면 구조가 바뀔 수 있고, 원하는 행을 안정적으로 하이라이트하기 어렵다. 따라서 DART API에서 저장한 원문 데이터를 우리 화면의 표로 그린다.

### 5.1 오른쪽 패널에 표시할 내용

- 재무제표의 모든 계정 행
- 계정 ID
- 계정명
- 당기 기간명
- 당기 금액
- 누적 금액
- 전기 기간명
- 전기 금액
- 통화

### 5.2 하이라이트 규칙

- 사용한 계정 행 전체: 연한 강조색
- 실제로 사용한 금액 칸: 진한 강조색
- 계산에 사용된 여러 행: 같은 번호 배지 표시
- 전기 비교값: 다른 색으로 구분
- 선택하지 않은 비슷한 계정: 하이라이트하지 않음

### 5.3 DART 원문 링크

오른쪽 패널에는 `DART 원문 열기` 버튼을 제공한다.

링크는 반드시 근거에 저장된 정확한 `rcept_no`를 사용한다.

```text
https://dart.fss.or.kr/dsaf001/main.do?rcpNo={rcept_no}
```

여러 보고서를 한 source로 묶은 뒤 가장 최신 보고서 링크를 사용하는 현재 방식은 제거한다.

각 검증 근거는 자신이 실제로 사용한 보고서 접수번호를 가져야 한다.

## 6. Excel 입력 대상에 저장해야 하는 정보

Excel의 각 입력 대상은 다음 정보를 가져야 한다.

```json
{
  "targetId": "revenue-2026-q1",
  "destination": {
    "sheetId": "sheet-income",
    "sheetName": "손익계산서",
    "address": "E12"
  },
  "metric": {
    "metricId": "revenue",
    "label": "매출액"
  },
  "period": {
    "type": "quarter",
    "year": 2026,
    "quarter": 1,
    "basis": "year_to_date"
  },
  "scope": "CFS",
  "targetUnit": "KRW_100M",
  "valueKind": "actual",
  "source": "DART",
  "dartRuleId": "revenue-rule-v1"
}
```

필수 항목은 다음과 같다.

1. 시트 ID
2. 시트 이름
3. 셀 주소
4. 지표 ID
5. 지표 이름
6. 연도
7. 분기
8. 연간·누적·단일 분기 구분
9. 연결·별도 구분
10. Excel 단위
11. 실제값·전망값 구분
12. 사용할 DART 계정 규칙

이 정보 중 하나라도 없으면 자동 입력 대상으로 만들지 않는다.

## 7. DART 계정 선택 규칙

지표마다 사용할 재무제표와 계정 규칙을 코드로 등록한다.

예:

```json
{
  "ruleId": "revenue-rule-v1",
  "metricId": "revenue",
  "allowedStatements": ["IS", "CIS"],
  "allowedAccountIds": [
    "ifrs-full_Revenue",
    "ifrs_Revenue"
  ],
  "allowedAccountNames": [
    "매출액",
    "영업수익",
    "수익(매출액)"
  ]
}
```

선택 순서는 다음과 같다.

1. 회사가 일치하는지 확인한다.
2. 사업연도가 일치하는지 확인한다.
3. 보고서 종류가 일치하는지 확인한다.
4. 연결·별도 구분이 일치하는지 확인한다.
5. 재무제표 종류가 허용 목록에 있는지 확인한다.
6. 계정 ID가 정확히 일치하는 행을 찾는다.
7. 계정 ID가 없을 때만 허용된 계정명으로 찾는다.
8. 후보가 정확히 한 개일 때만 선택한다.

후보가 0개이거나 2개 이상이면 자동 선택하지 않는다.

LLM이나 문자열 유사도로 가장 비슷한 행을 고르지 않는다.

---

## 8. 기간과 보고서 선택 규칙

### 8.1 보고서 코드

| 필요한 기간 | DART 보고서 |
|---|---|
| 1분기 | 1분기보고서 `11013` |
| 상반기 | 반기보고서 `11012` |
| 3분기 누적 | 3분기보고서 `11014` |
| 연간 | 사업보고서 `11011` |

### 8.2 단일 분기 계산

| 필요한 값 | 계산 |
|---|---|
| 1분기 단독 | 1분기 누적 |
| 2분기 단독 | 반기 누적 - 1분기 누적 |
| 3분기 단독 | 3분기 누적 - 반기 누적 |
| 4분기 단독 | 연간 - 3분기 누적 |

### 8.3 재무상태표

자산·부채·자본은 특정 날짜의 잔액이므로 빼기 계산을 하지 않는다.

### 8.4 공시 기준일

프로젝트 기준일 이후에 나온 보고서는 사용하지 않는다.

정정공시가 여러 개라면 기준일 이전에 공시된 가장 최신 정정본을 사용한다.

보고서가 아직 나오지 않았다면 이전 기간 값을 대신 넣지 않는다.

## 10. Excel 숫자 검증 규칙

Excel 숫자는 다음 검사를 모두 통과해야 한다.

1. 회사 코드 일치
2. 사업연도 일치
3. 보고서 코드 일치
4. 공시일이 기준일 이전
5. 연결·별도 범위 일치
6. 재무제표 종류 일치
7. 계정 ID 또는 허용 계정명 일치
8. 기간 일치
9. 누적·단일 분기 구분 일치
10. 숫자 변환 가능
11. 통화 확인
12. 단위 변환 가능
13. 후보 행이 정확히 하나
14. Excel 목적지 셀 일치
15. 수식 셀이 아님
16. Excel 구조가 처음 분석했을 때와 동일

하나라도 실패하면 자동 입력하지 않는다.

## 11. 검증 상태

Excel 입력 대상마다 다음 상태 중 하나를 표시한다.

| 상태 | 의미 |
|---|---|
| `검증 완료` | 값과 원문을 모두 확인함 |
| `사용자 승인 완료` | 사용자가 변경안을 승인함 |
| `공시 전` | 필요한 보고서가 아직 없음 |
| `계정 없음` | 계정 행을 찾지 못함 |
| `계정 후보 여러 개` | 자동 선택할 수 없음 |
| `기간 불일치` | 보고서와 Excel 기간이 다름 |
| `범위 불일치` | 연결·별도 구분이 다름 |
| `단위 확인 필요` | 단위를 결정할 수 없음 |
| `수식 셀` | 값을 덮어쓸 수 없음 |
| `Excel 변경됨` | 분석 후 Excel 구조가 바뀜 |
| `사용자 검토 필요` | 자동 처리를 중단함 |

오류 상태에서는 승인 버튼을 비활성화한다.

## 12. 가설 조사 결과 검증 수정사항

Excel 검증 외에 가설 질문 검증도 함께 수정한다.

### 12.1 모든 근거 표시

현재처럼 첫 번째 근거만 보여주지 않는다.

질문에 연결된 모든 근거를 목록으로 보여준다.

- 지지 근거
- 반대 근거
- 참고 근거
- 실패한 근거

### 12.2 대표 답변 생성

첫 번째 통과 결과를 대표 답변으로 사용하지 않는다.

질문의 필수 지표가 모두 검증된 뒤에만 대표 답변을 만든다.

대표 답변에는 사용한 근거 ID를 함께 저장한다.

### 12.3 지표 ID 사용

자유로운 제목 문자열로 지표 충족 여부를 확인하지 않는다.

모든 조사 결과는 질문에 등록된 `metricId`를 가져야 한다.

### 12.4 충돌 자동 생성

같은 지표와 기간에 서로 다른 값이 있으면 자동으로 충돌을 만든다.

예:

```text
DART 매출액: 1조 2,000억원
IR 매출액: 1조 2,300억원
```

사용자가 사용할 출처를 선택하기 전까지 질문을 승인할 수 없다.

### 12.5 질문별 재조사

재조사 버튼을 누르면 전체 계획을 다시 조사하지 않는다.

선택한 질문과 지표만 다시 조사한다.

기존의 다른 질문 결과는 유지한다.

### 12.6 출처별 원문 패널

출처에 따라 오른쪽 패널을 다르게 표시한다.

| 출처 | 오른쪽 패널 |
|---|---|
| DART | 재무제표 표와 사용한 행·금액 하이라이트 |
| 기업 IR PDF | 사용한 페이지와 문장 하이라이트 |
| 사용자 PDF | 사용한 페이지와 문장 하이라이트 |
| 뉴스 | 저장된 기사 본문과 문장 하이라이트 |
| KRX | 사용한 날짜와 데이터 행 하이라이트 |
| ECOS | 사용한 통계 항목과 시점 하이라이트 |

외부 URL은 원본 확인용 보조 버튼으로 제공한다.

## 13. 사용자 승인 규칙

### 13.1 Excel 변경안

사용자는 각 변경안을 다음 중 하나로 결정한다.

- 승인
- 거절
- 값 수정

결정하지 않은 변경안을 자동 승인하지 않는다.

### 13.2 전체 승인

`전체 승인`은 다음 조건을 모두 만족할 때만 가능하다.

1. 모든 필수 Excel 값이 검증 완료
2. 모든 필수 변경안을 사용자가 승인
3. 해결되지 않은 충돌이 없음
4. 공시 전 상태인 필수 값이 없음
5. 계정 후보 여러 개 상태가 없음
6. Excel 구조가 변경되지 않음

### 13.3 다음 단계 이동

다음 단계 버튼은 다음 조건에서만 활성화한다.

- 모든 필수 가설 질문 검증 완료
- 모든 필수 Excel 값 검증 완료
- 모든 필수 Excel 변경안 승인 완료
- 검증된 Excel 사본 생성 완료
- 저장 후 Excel 재검사 완료

## 14. Excel 반영 과정

1. 승인된 변경안만 가져온다.
2. 원본 Excel 파일 hash를 확인한다.
3. Excel 구조 hash를 확인한다.
4. 대상 시트와 셀을 다시 확인한다.
5. 수식 셀 여부를 다시 확인한다.
6. 승인된 값을 Excel 사본에 입력한다.
7. 원본 파일은 변경하지 않는다.
8. 새 Excel 파일을 저장한다.
9. 새 Excel을 다시 연다.
10. 승인된 값이 정확한 셀에 들어갔는지 확인한다.
11. 승인하지 않은 셀이 변경되지 않았는지 확인한다.
12. 수식·시트·병합 셀·차트가 유지됐는지 확인한다.
13. 결과 파일과 검증 기록을 저장한다.

## 15. 서버 수정사항

### 15.1 Research Agent에서 Excel 숫자 제거

Research Agent는 가설 질문만 조사한다.

Research Agent 요청에서 `excelTargets`를 제거한다.

Research Agent 출력에서 `category: "excel"`을 제거한다.

### 15.2 DART 규칙 엔진 추가

다음 모듈을 추가한다.

```text
dart-report-resolver.ts
dart-account-registry.ts
dart-row-resolver.ts
dart-period-calculator.ts
dart-value-validator.ts
```

각 모듈의 역할은 다음과 같다.

- `dart-report-resolver`: 정확한 보고서와 정정본 선택
- `dart-account-registry`: 지표별 계정 ID와 계정명 관리
- `dart-row-resolver`: 정확한 재무제표 행 선택
- `dart-period-calculator`: 누적값을 단일 분기값으로 계산
- `dart-value-validator`: 기간·범위·단위·금액 검증

### 15.3 DART 보고서 별도 저장

연간보고서와 분기보고서를 하나의 source에 섞지 않는다.

보고서 하나마다 별도 source version을 만든다.

각 source version은 자신의 `rcept_no`와 원문 URL을 가진다.

### 15.4 검증 근거 API 추가

오른쪽 패널에서 사용할 API를 추가한다.

```text
GET /api/projects/{projectId}/validation/evidence/{evidenceId}
```

DART 근거 응답에는 다음을 포함한다.

- 보고서 정보
- 재무제표 정보
- 전체 재무제표 행
- 선택한 행 ID
- 선택한 금액 칸
- 계산식
- 원문 URL

### 15.5 Excel 변경안 자동 승인 제거

사용자 결정이 없는 변경안은 `미결정` 상태로 유지한다.

미결정 변경안이 하나라도 있으면 Excel 반영 작업을 시작하지 않는다.

## 16. 화면 수정사항

### 16.1 Excel 셀 선택

- Excel 시트에서 검증 대상 셀을 클릭할 수 있게 한다.
- 변경안 목록을 클릭해도 같은 셀이 선택되게 한다.
- 선택한 셀은 Excel 화면에서도 강조한다.

### 16.2 오른쪽 원문 패널

- 선택한 셀에 연결된 출처를 자동으로 연다.
- DART 표를 내부 화면으로 표시한다.
- 선택한 행과 금액 칸을 하이라이트한다.
- 계산값은 모든 원문과 계산식을 표시한다.
- 정확한 DART 원문 링크를 제공한다.

### 16.3 근거 전환

한 값에 근거가 여러 개면 탭으로 전환한다.

예:

```text
[DART 권위 출처] [기업 IR 확인 출처]
```

권위 출처와 확인 출처를 명확히 구분한다.

### 16.4 승인 버튼

원문 패널을 열지 않았더라도 승인할 수는 있지만, 사용자가 확인하지 않은 상태를 표시한다.

권장 흐름은 원문 확인 후 승인이다.

오류가 있는 값은 승인할 수 없다.

## 18. 완료 조건

다음 조건을 모두 만족해야 작업이 완료된 것으로 본다.

1. Excel 숫자 선택 과정에서 LLM을 사용하지 않는다.
2. 모든 DART Excel 값이 정확한 `targetId`를 가진다.
3. 모든 DART Excel 값이 정확한 보고서 접수번호를 가진다.
4. 모든 DART Excel 값이 재무제표 코드와 계정 정보를 가진다.
5. 모든 DART Excel 값이 사용한 금액 칸을 기록한다.
6. Excel 값을 클릭하면 오른쪽 패널에 정확한 DART 재무제표가 열린다.
7. 사용한 계정 행과 금액 칸이 하이라이트된다.
8. 계산값은 모든 원문과 계산식을 보여준다.
9. DART 원문 링크가 실제 사용한 접수번호와 일치한다.
10. 첫 번째 근거만 보여주는 문제를 제거한다.
11. 충돌을 자동으로 만들고 사용자가 해결할 수 있다.
12. 재조사는 선택한 질문과 지표만 다시 실행한다.
13. Excel 변경안을 자동 승인하지 않는다.
14. 승인된 값만 Excel 사본에 반영한다.
15. 결과 Excel을 다시 열어 검증한다.
16. 각 Excel 셀에서 DART 원문까지 전체 연결을 추적할 수 있다.

최종 연결은 반드시 다음과 같아야 한다.

```text
Excel 결과 파일
→ 시트와 셀
→ 입력 대상 targetId
→ 검증된 값
→ DART 계정 행과 금액 칸
→ 재무제표
→ 보고서 접수번호
→ 저장된 DART 원문
```
